# 0.10.0 device regression

Tested on 2026-10-26 with an Xcode 26.5 Release build (iPhoneOS and AppleTVOS SDK 26.5). Both targets were vphone guests on JP02; these results do not certify physical hardware or other system versions.

| Target | Guest | Device regression | Reboots | Library host |
| --- | --- | --- | --- | --- |
| JP02, iPad template | iPadOS 27.0.1 `24A446`, `iPad15,3`, RootHide | IOS_RESULT | IOS_REBOOTS | Versioned package consumer passed on the device, including a host `api()` handler and its `ProbeAPIError` code |
| JP02, Apple TV HD template | tvOS 26.6 `23L773`, `AppleTV5,3`, no bootstrap | 11/11 passed | userspace and full reboot passed | vphoned's session process on IcliKit's probe: 15/15 |

## iOS

The regression command was `python3 scripts/acceptance.py --layout roothide`, a full run including the reboot group, with root SSH logins. IOS_DETAIL

`springboard_restart` fails on this guest for 0.9.2 as well: after the second respring the iPad unlocks with `button wake` and locks itself again within a second, so the case's last check sees it locked. An A/B run with the official 0.9.2 DEB fails at the same place. The reboot group, which runs after it, then starts on a locked iPad and is refused with `device_locked`; run on its own with the iPad awake, `userspace_reboot` and `device_reboot` passed with this binary. `account_password` ran without OpenSSL on the Mac: only LibreSSL's `openssl`, which cannot compute `passwd -6`, was on the runner's PATH.

## tvOS

`python3 scripts/tvos-acceptance.py --vm tvhd --respring` ran 11 cases against the tvOS binary with SHA-256 `db9fc1fb4d1fc0615dbc7b9044d3c815215149b0f90749b276cf1de1807aafb6`: environment, read-only commands, the unavailable answers, the launchd life cycle with kickstart replacement, registration and launch, a container install, files, preferences and Keychain, device controls, the screen saver, `icli probe` and a PineBoard restart. All passed, run straight after the guest booted.

`button wake` on the screen saver was then checked 16 times, 10 on a settled guest and 6 straight after boot: each time HeadBoard came back and no app opened. Earlier builds pressed Select alone, which right after boot could be swallowed or, once the screen saver was already going, reach HeadBoard and open the focused app; PineBoard's `deactivateScreenSaver` alone is ignored while the screen saver is coming up. The release asks PineBoard first and presses Select only if the screen saver is still there 1.5 s later.

A userspace reboot replaced PineBoard and kept the kernel; a full reboot changed the boot session, and HeadBoard came back after each. Three `sb respring` runs kept the kernel. This guest's `uptime_seconds` hardly advances while the VM is idle, so reboots are judged by the boot session and PineBoard's pid, not uptime.

A local rebuild of the same sources after testing gave a tvOS binary that differs from the tested one only in its `LC_UUID` and code signature: the iOS and tvOS builds share one SwiftPM scratch folder, and the linker's debug map records object timestamps. CI builds its own binaries; their hashes are in the release's `package-verification.json` and `SHA256SUMS`.

## vphoned on the probe

vphoned's script session was moved onto IcliKit's `evaluateProbe` and `runProbeREPL(api:)` in a local vphone-cli build whose icli dependency pointed at this candidate. Run as `--session eval` and `--session repl` on both guests, it answered one JSON line, collected output, reported a throwing script, reached ObjC and the guest API in process with vphoned's own error codes, ran a program through `proc.run` with stdin and exit status, capped its arguments, ended with `exit(code)`, and ran the REPL with multi-line statements. On the iPad's terminal, ^C abandoned a half-finished statement and ended the session during a runaway one.

## Host gates

`test-probe.sh` (149 checks), `test-sha512-crypt.sh` (8 known answers), and the archive/locale, launchd-plist, foreground-UID, RootHide-root and syslog regressions passed. Both binaries passed the process-launch, deployment-floor and JavaScriptCore-link checks; the iOS DEBs and the tvOS DEB passed the package checks; all three products built as exact-version consumers for iOS 15 and tvOS 15.
