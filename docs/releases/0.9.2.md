- Add virtual-pointer input on iPad from [PR #13](https://github.com/owngoal-dev/icli/pull/13): `screen click` supports primary, secondary and middle buttons, click count, hold duration, hover and normalized coordinates; `screen scroll` scrolls the view under the pointer without momentum. Existing touch commands are unchanged.
- IcliKit exposes `pointerMove`, `pointerButtons`, `pointerScroll`, `pointerClick` and `pointerScrollGesture`. Each process owns one virtual HID device until it exits. Button changes use explicit events so a long-lived device does not leave buttons stuck down or interfere with another process's clicks.
- The CLI signing profile adds `IOHIDResourceDeviceUserClient` to `com.apple.security.iokit-user-client-class`. Hosts using the new IcliKit APIs need that entry in their own signing profile. On iPhone, pointer interaction requires AssistiveTouch pointer-device support.
- Targeted smoke checks passed on JP02, iPadOS 27.0.1 with RootHide: both new CLI acceptance cases, six clicks in one persistent IcliKit process, low-level and whole-gesture scrolling, a subsequent normalized CLI click and invalid-argument rejection. The initial run was blocked by the system's Trust This Computer alert; pointer click dismissed it and the checks then passed. Local build, binary, entitlement and both DEB checks passed. This patch did not rerun the full device regression or Irisin upgrade tests.
