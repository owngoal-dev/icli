- IcliKit adds `InterfaceGeometry` and `withInterfaceGeometry` (from [PR #19](https://github.com/owngoal-dev/icli/pull/19)). A library host that knows the active display's geometry, such as a foldable's inner display, can run a synchronous block against one validated snapshot of it. Screen metrics, accessibility visibility and coordinates, and touch and pointer normalization then use that snapshot. Screenshots, OCR and `screen describe` are refused inside the scope, because geometry alone does not choose a display to capture. Outside a scope, nothing changes. Details are in [the package guide](https://github.com/owngoal-dev/icli/blob/1.0.0/docs/swift-package.md).
- `scripts/test-interface-geometry.sh` checks rotation, validation, nested and throwing scopes, per-thread isolation and the capture guard, and runs in the release workflow.
- The CLI and its JSON answers are the same as 0.11.0.

## Device regression

The no-scope path was compared with 0.11.0 on vphone guests with RootHide:

- iPad Air (M3), iPadOS 26.4: the `ax`, `gestures`, `screen`, `input` and `controls` acceptance groups passed (27 cases). `pointer_scroll` failed once in the group run and then passed three times on its own with both versions.
- iPadOS 27.0.1: the `ax` and `gestures` groups fail the same way with 0.11.0, because TestHost opens as a floating window there.
- iPhone, iOS 26.4 and 27.0.1: `screen info`, `ui tree`, `ui at`, `ui tap`, rotation and the on-device self-tests gave the same output with both versions. The iPhone landscape path was not exercised: Settings stays in portrait.

The new scope itself has been checked on a device only through a backport of the same code to 0.10. The full acceptance suite and the reboot group were not rerun for this release.
