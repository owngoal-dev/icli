The regression command was `python3 scripts/acceptance.py --layout roothide --skip-reboot`, using root SSH logins. Userspace and full reboots were not rerun, so these are not full acceptance runs for `assemble-release.py`. Location Services were off: the location case verified refusal, and the recorded command inventory leaves `location clear` unobserved. Vision text recognition was unavailable on these guests; the tests verified the explicit unavailable response against TestHost's independent Vision request. The iPad fixture was run full screen with system dialogs dismissed. The kickstart case was also rerun successfully with mobile SSH logins and sudo, verifying fixture upload/ownership and the unprivileged refusal through the default runner path. Both VMs were stopped after testing.

The signed CLI tested on both devices and packaged in both local DEBs has SHA-256 `429d55a4e55112db06199af63bffa6f92bfd2ffb2de6c5e3a1c1005ba916b0eb`. CI builds its own binaries; their hashes are in the release's `package-verification.json` and `SHA256SUMS`.

## Daemon replacement

`launchd_kickstart_upgrade` runs a test daemon that writes its version and PID. It verifies that start and kickstart without `-k` keep version 1 running after an atomic replacement of its executable, then `kickstart -k` runs version 2 with the PID returned by launchd. It also checks invalid and missing labels and refusal as mobile. This exposed two iOS 27 differences before release: kickstart needs service-attach, and an unchanged job can return status 0 instead of EALREADY. A root check in the public API prevents the added entitlement from allowing a mobile caller to change a service.

## Irisin integration and the next operation

Both devices passed the following sequence through Irisin's actual Mach-service client and detached helper, with the client running as mobile:

1. Install the packaged Irisin integration build through a daemon-run transaction, register the updated app, and launch it again.
2. Connect to the installed daemon again, install icli 0.9.0 as the baseline, then upgrade it to 0.9.1 through Irisin. Verify the CLI's version, native environment report and installed package record.
3. Install the data-only `dev.owngoal.icli.installtest` fixture through a fresh connection, read its marker, remove it through another transaction, and verify it is gone.

The downstream build was Irisin 4.7.2, source `0cffa96234ad268b4d77e2f9eae4fee2e24e8542`, test build 900091, with its IcliKit dependency pointed at the local candidate source. The packaged test DEB's SHA-256 was `8e500eec55ad4ed3e05404524dcbed1e0f84922bc52c89d6e02eed584ab7cde8`. This was a local integration build, not a published Irisin release; the original Irisin checkout was not changed.
